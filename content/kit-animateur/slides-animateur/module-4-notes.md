# Notes présentateur — Module 4 — Créer des solutions numériques avec Claude Code

Numérotation alignée sur `modules/module-4-solutions-numeriques/03-support-slides.md`. Le script d'ouverture/clôture mot à mot est dans `kit-animateur/run-of-show-session-4.md` — ce fichier couvre les slides intermédiaires, pas répétées ici.

| Slide | Ce qu'il faut dire (pas seulement montrer) |
|---|---|
| 1 — Titre | Laisser la slide 5-10 secondes en silence pendant que les derniers participants arrivent, puis dérouler le script d'ouverture de `run-of-show-session-4.md` (le callback DELTA Distribution/Module 3). |
| 2 — Section "Partie 1/5" | "Dans les trois premiers modules, vous avez toujours demandé UN fichier à Claude — un compte-rendu, un notebook, un tableau nettoyé. Ce soir on change d'échelle : on va demander un projet, plusieurs fichiers qui travaillent ensemble. Et la seule chose qui décide si ça marche du premier coup, c'est la qualité de ce qu'on décrit au départ." |
| 3 — 4 éléments d'une bonne description | Commenter chaque puce avec l'exemple de Fatou déjà sur la slide, sans le relire mot pour mot — insister sur "les données disponibles" : "c'est la puce que tout le monde oublie, et c'est celle qui fait que Claude Code invente une structure qui ne correspond à rien de réel." Terminer sur l'encadré "À retenir" en le lisant lentement, une seule fois. |
| 4 — Citation Fatou | Ton posé, presque anecdotique : "Un fichier Excel envoyé en espérant qu'il soit ouvert, contre un lien envoyé en sachant qu'il le sera. C'est tout l'enjeu de la session, dans une phrase." |
| 5 — Section "Partie 2/5" | "Les données que je vais utiliser là, ce ne sont pas des données inventées pour l'exemple — c'est exactement le fichier que Fatou a nettoyé au Module 3. Ce qui change, c'est qu'on ne va plus les lire dans un tableau, on va les voir." |
| 6 — 4 blocs du dashboard | Nommer les 4 blocs en les pointant un par un, pas en les lisant en bloc : indicateurs, alerte Nord, évolution mensuelle, répartition par canal. Sur l'encadré "À retenir", ralentir : "Ce dashboard ne fait que confirmer avec des chiffres ce que le client de Fatou avait déjà remarqué à l'oreille en réunion — c'est ça, la valeur d'une donnée bien restituée." Enchaîner directement sur le sous-bloc A de la démo. |
| 7 — Section "Partie 3/5" | "On change complètement d'objectif ici. Le dashboard restitue une donnée qui existe déjà. La page vitrine, elle, doit convaincre quelqu'un qui ne connaît pas encore Fatou de la contacter." |
| 8 — Structure qui convertit | Lire la liste comme une checklist qu'on cochera plus tard : en-tête, problème, offre, preuve, tarif, appel à l'action. Insister sur l'encadré : "Zéro jargon technique visible — si votre client lit le mot 'API' sur votre page, vous avez déjà perdu son attention." |
| 9 — Section "Partie 4/5" | Baisser le rythme, ton presque solennel : "C'est la partie la plus importante de la soirée, pas techniquement, mais pour votre confiance. Une erreur qui s'affiche à l'écran n'est pas un jugement sur vous. C'est une étape normale, avec une méthode." |
| 10 — 4 étapes avant de corriger | Détacher chaque étape avec une micro-pause : "Lire l'erreur en entier... demander un diagnostic, pas une correction... vérifier l'hypothèse vous-même quand c'est simple... corriger de façon ciblée, puis vérifier le fond." Sur l'encadré : "'Ça ne marche toujours pas', répété sans nouvelle information, c'est une boucle sans fin — Claude Code ne peut pas deviner ce qu'il ne voit pas." |
| 11 — Le bug de l'exercice, en direct | Pointer la ligne de code affichée, puis le message d'erreur juste en dessous, sans les paraphraser : laisser le silence faire l'effet. Puis : "Retenez juste ce nom : `montant_total_fcfa`. C'est exactement le bug que vous allez rencontrer dans dix minutes dans votre propre exercice — je vais le provoquer devant vous tout de suite." Bascule immédiate vers le sous-bloc B de `05-demo-commentee.md`. |
| 12 — Section "Partie 5/5" | "Dernière étape, et c'est celle que tout le monde a tendance à sauter parce qu'elle semble administrative. Sauf qu'un projet qui ne tourne que sur votre machine n'est un livrable pour personne d'autre que vous." |
| 13 — Un lien, pas un fichier | Nommer les deux chemins selon le type de projet (Streamlit Community Cloud pour un dashboard, Netlify/Vercel/GitHub Pages pour un site) sans détailler les étapes — elles arrivent dans la démo. Sur l'encadré : "Gratuit, réversible, sans risque pour votre machine — la peur de 'casser' quelque chose en déployant n'a pas lieu d'être." Si la question "pourquoi pas juste envoyer le fichier ?" arrive dans le chat, elle est déjà anticipée : un lien reste à jour, un fichier envoyé par email ne l'est plus dès le mois suivant. |
| 14 — Livrable (badge) | Nommer explicitement les deux images à voix haute en pointant le badge : "Avant : un fichier Excel envoyé par email, jamais rouvert. Après : une application ou un site déployé, accessible par un lien. C'est ce basculement-là que vous devez avoir fait avant mercredi." |
| 15 — Clôture / CTA | Dérouler le script de clôture de `run-of-show-session-4.md` (défi, Section 4 du Portfolio, teaser Module 5), ne pas improviser un résumé différent ici. |
